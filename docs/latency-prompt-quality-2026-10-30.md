## 结论与边界

候选在已测两个边界各一次通过，基线在缺长文条件下耗尽输出上限。这提示原句序在该输入上可能更容易反复处理规则，但仅单次配对，不能断言原因是句序，不能宣布候选等质量或更快。裁切与开放问答尚未测试，完整日常题也尚未在候选上测试；质量门槛未完成，候选不部署。

保持 2048 上限原样记录失败，不增加上限后重跑，不把基线失败删除或计为“零秒答案”。该上限为本轮明确获批参数；此前 Vercel 敏感值 API 无法重读生产实际上限，不能外推成线上一定存在相同问题。基线和候选本轮使用同一现有本地 API 密钥、同一机器、端点和参数，只有提示词句序不同。

这是本机直接供应商质量筛查，没有实际热键、截图、官方准入结算和 UI 绘制，不记录或声称生产端到端提速。原六题实测平均仍为 **8.056 秒，目标未达**。性能报告不包含图片或答案正文；私有质量证据保留在 `/tmp/notchspi-prompt-quality-20261030/run`，正常终止，无后台请求待完成。

## 后续批次的真实结果：第 1 次再次停止

用户明确允许继续未测的 4 次、总预算不增加。实际后续只调用 1 次：裁切选项、A 基线，输入 629 / 输出 280 token，finish_reason=stop，机器协议为 ready/none，正文含 FINAL。普通协议解析没有 violations，但题图底边截断 C、完全缺少 D，质量门槛要求 retake/cropped，因此失败。运行器随后停止，B 裁切与作文 B/A 三次均未执行，没有重试。不能把“格式有效”写成“完整性有效”，也不能把此次 A 失败归于尚未调用的 B。

两批累计 5 次、输入 5923 / 输出 3428 token。按峰时价估算总费用 US$0.0058905，非账单核验，未超过 US$0.10 预留。后续原始证据位于 `/tmp/notchspi-prompt-quality-20261030/run-remaining/`，退出记录 `calls=1, passed=false, stopped=quality_gate`。该批许可也已 claimed。还有 3 个未测样本，但再次停止后不得自动启动下一批。

代码复核发现一处相关表述缺口：默认提示词仅定义 retake 的字段与原因，并未像现有 briefScreenPrompt 一样明确要求先检查“全部题干、所有必需选项与引用材料实际可见”，也未明确禁止用可推算答案替代缺失文本。这与本次失败相容，但单个真实样本不能证明唯一因果。decision-order-v1 逐字保留基线，因此也保留这处表述缺口；重新排序不能自动补出缺失的强制条件。下一步应先评估最小完整性前置检查，保留现有字段、限额及所有原始失败，不通过降低质量门槛让本次样本过关。

尚未修改生产提示词或开启 briefScreenPrompt；后者还会增加可见计算摘要，不能作为无副作用的替换。候选质量仍未通过完整门槛，端到端均值仍是 8.056 秒。后续机器可读记录：[remaining samples](latency-prompt-quality-remaining-2026-10-30.samples.json)。
