# 2.12 截图超时恢复（本地修复）

用户反馈当前 Mac 上 2.12 持续提示“系统截图服务响应超时”。本机为 macOS 26.5.2；历史诊断已确认 SCShareableContent 曾耗时 52 秒，图片回调也曾超时。原保护只限制调用者等待，不能恢复卡住的系统服务。本次没有重启系统服务或整机。

## 用户回测与权限流程修正

安装首个修复包后，用户回测仍失败；切换目标到全屏才出现系统授权弹窗，允许后全屏恢复，再切回 Chrome 也正常。这是本次故障与授权状态关联的直接证据，不能把早先其他测试中的服务长等待当作本次唯一原因；首个备用截图补丁不足以独立解决用户问题。弹窗类型和先前的实际 preflight 返回值没有记录，不能进一步认定具体 TCC/周期授权机制。

代码检查发现，原本只有引导页主动调用 CGRequestScreenCaptureAccess，普通捕获未统一检查并申请权限，窗口枚举还把所有普通错误归为无权限。后续新增 CapturePermission：全屏和应用目标进入同一授权入口，未获准时先请求授权，拒绝后不进入枚举/超时恢复；已授权则直接继续原目标。自动模式启动也复用权限申请，后台预热和 hash 采样在无权限时退出，不主动申请。错误分类优先识别当前无权限与 ScreenCaptureKit 的 userDeclined，真正的服务超时保留回退能力，其他系统错误不再一律伪装成权限缺失。权限文案只在 macOS 要求时提示重启。

后续完整 Swift 320 项、4 跳过、0 失败；4 跳过为 2 项付费模型和 2 项显式实机截图测试。新增测试覆盖授权后继续 Chrome 原目标、拒绝不开始截图、已有权限不重复申请、取消不弹窗、系统明确拒绝及真实服务错误分类。没有重置用户权限来复现首次授权，也不能凭模拟依赖测试宣称所有系统授权弹窗都已实测。后续包生成于 dist-qa；用户已恢复正常，当前 /Applications 保持首个已授权修复包。

## 修复行为

- 保留 ScreenCaptureKit 正常截图、合并枚举和单次 10 秒等待保护。明确超时或在途操作 busy 后自动使用 `/usr/sbin/screencapture`；正常权限、目标不存在等错误不触发回退。
- 60 秒内后续请求直接使用备用路径，每次重新截图，不交付旧截图；暂停预热和自动 hash 采样，期限结束才再探测 ScreenCaptureKit。自动模式在此间没有新增 hash 帧。
- 全屏回退先返回 panelNotExcludable，由控制器沿既有路径隐藏面板、等待 130ms 再拍摄。第二次调用仍使用备用路径，不会重新等待原枚举。应用目标按 PID、层级、尺寸及屏幕状态选择精确窗口 ID，以 `-l` 拍摄，失败不会扩大为全屏。
- 子进程最多等待 5 秒；取消或超时终止本次子进程，确认退出后才允许新进程。取消后的图片不继续编码。命令输出在 0700 私有临时目录，完成即删除；最终 JPEG 仍由现有生命周期管理，权限 0600，长边最多 1568px。
- 两种方式均失败时，提示结束录屏/共享再试，持续失败则重启 Mac，避免一直要求重启 App。
