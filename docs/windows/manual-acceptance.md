# Windows 实机验收清单（照着做版）

> 验收记录始于 2026-10-19，后续更新以各段日期和关联记录为准。本文的运行状态、测试计数和待验收项属于各次记录时点；2026-10-23 的提交整理没有执行 Windows 实机验收。

本手册适用 NotchSPI 3.0 build 27（Windows 文件名版本 3.0.27），整理日期2026-10-19。当前Windows包尚未做实机验收，也未签名。这份清单是要你去验证的目标，不代表这些项目已经通过。

你不需要懂代码。照着“怎么做”操作，再对照“什么算通过”。先做A，再按设备条件做B，C中需要开发者的项目约人一起做。

每项选一个结果：**未测**＝还没操作；**通过**＝本项所有已要求条件都观察到了；**不通过**＝实际表现不符合；**缺条件**＝缺屏幕、额度、权限或测试环境。部分步骤没做，在备注逐条写，整项不要选通过。

基本一轮预计45～60分钟；双屏和开发者配合另计。应用会把截到的题图送给当前查题服务，因此只使用附带练习材料，避免私人聊天、账号资料进入截图。此练习页只是题目素材，不能替应用生成答案。

## 开始前准备

1. 拿到两个东西：应用包 NotchSPI-3.0.27-Windows-x64.zip，以及本手册资料包。资料包里没有应用本体，需要分别接收。
2. 优先用Windows 11、x64电脑。按Win + I打开设置→系统→关于，查看“系统类型”。x64不是ARM；32位或ARM机器请先让开发者确认，不能记成x64通过。Windows 10如需覆盖，要求2004（build 19041）或更新版本以支持截图排除，并另外填一份结果。
3. 准备联网、鼠标、手机（拍照/录像），最好还有第二块显示器。先关闭其他版本NotchSPI，避免相同快捷键互相抢占。
4. 向开发者拿测试账户/额度及本次允许使用的次数；没有就先测纯界面。免费体验一旦主动领取就开始计时，不要在他人的常用账户上代领。
5. 解压资料包后双击 checklist.html，用Edge或Chrome打开；点“打开练习题”会打开 practice.html。请把两个文件留在同一文件夹。
6. 在桌面新建“NotchSPI验收记录”，把照片/视频放进去。文件名用项目编号，例如 A07-两图-视频.mp4、B03-左屏100右屏150.jpg。

应用文件：NotchSPI-3.0.27-Windows-x64.zip；大小 158,984,377 字节。SHA-256：557734ac82fa4f937fe35203c651525d90ce07c539cf5c8e84285d4eb83f72c9。这串摘要供开发者核对是否同一个包，测试者不用手工计算。应用更新后需重新确认文件版本和清单。

## 先认识几个名字

- **顶部面板/刘海**：屏幕最上方的黑色小面板。Windows没有物理刘海也能显示。
- **Ghost**：面板里的白色小幽灵，用来表示空闲、思考、完成等状态。
- **托盘**：右下角时钟旁的小图标区域；图标可能藏在“^”里。
- **快捷键**：同时按住几个键。例如Ctrl + Shift + 1：按住Ctrl和Shift，再按键盘上排的1，随后松开。优先不用小键盘。
- **单图/多图**：单图：截一张就查；多图：同一道题分成2～4张，最后一张放问题，前面放材料。
- **窗口目标**：只截选中的浏览器等一个窗口。整个屏幕则按鼠标所在屏幕截取。
- **缩放/刷新率**：缩放是系统的100%/150%等界面大小比例；刷新率是60/120/144Hz等画面更新速度。

### A01 · 完整解压，启动，退出，再启动

**结果：□ 未测　□ 通过　□ 不通过　□ 缺条件**

怎么做：

1. 找到 NotchSPI-3.0.27-Windows-x64.zip。右键它，点“全部解压缩…”（有的电脑叫“解压全部”）。选一个容易找到的文件夹，例如桌面上的 NotchSPI测试，点“提取”。
2. 等解压结束，打开新文件夹。找到并双击 NotchSPI Desktop.exe。若看不到 .exe，找名称为 NotchSPI Desktop、类型为“应用程序”的文件。
3. 保留同一文件夹里的全部文件。不要在压缩包窗口里直接运行，也不要只拖出一个 exe。普通启动不需要安装 Node、Python，也不需要先以管理员身份运行。
4. 看屏幕顶部有没有黑色小面板或白色小幽灵。再看右下角时钟旁边的图标，藏起来时点“^”。右键 NotchSPI 图标可打开菜单。
5. 从菜单点“退出”，确认它消失。再双击一次 exe，确认重新出现。再双击一次 exe，观察是否只保留一个应用。
6. 如果出现“Windows 已保护你的电脑”、文件被隔离或需要管理员密码：先拍照，填“缺条件/启动被拦截”，交开发者核对文件和处理。不要关闭杀毒软件或自行放行。30秒还看不到应用时先查托盘，不要连续双击。

什么算通过：

- 能从解压后的文件夹启动；顶部面板或托盘菜单可操作。
- 退出后消失，重新启动正常；重复打开不会出现两个面板、两组菜单。

证据：启动后的顶部面板照片；被拦截时拍完整提示。

### A03 · 完整走一遍首次引导

**结果：□ 未测　□ 通过　□ 不通过　□ 缺条件**

怎么做：

1. 首次启动在欢迎页点“试一道题”；没有欢迎页时，从应用菜单点“使用引导”。浏览器应打开本地练习页。
2. 把题干和选项完整放进屏幕，按 Ctrl + Shift + 1。等实际答案出现，应进入“试试多图模式”，不能只点按钮就假装答完。
3. 点“试试多图模式”。浏览器先选“材料”，按 Ctrl + Shift + 2；再选“问题”，再按一次同样快捷键。两张录入后停止操作，等约4秒自动查题。
4. 结果出现后点“继续”。体验已开启的账户应显示已开启；未领取的账户可选择“稍后领取”。点“开始使用”或对应完成按钮结束引导。
5. 再打开“使用引导”，在截图练习阶段点“稍后继续”，退出并重新打开应用，再从菜单进入引导。观察能否从合理的练习步骤继续。

什么算通过：

- 练习页能打开；单图与多图都经过真正截图、等待和结果。
- 失败时不会被当作成功；完成单图后才进入多图，完成多图后才进入最后一步。
- 关闭不等于完成；重新进入可以继续，不会凭空显示已经答完。
- 练习记录不应进入普通“最近查题”；后面的A04再验证日常历史。

证据：首题结果、多图结果、最后体验页各一张；最好连续手机录像。

### A04 · 日常单图查题、复制、历史

**结果：□ 未测　□ 通过　□ 不通过　□ 缺条件**

怎么做：

1. 完成或暂时退出引导。打开本清单附带的 practice.html，选“单题1”，只让练习页显示在要截的区域。
2. 到“设置”→“通用”→“截图目标”选练习所在浏览器窗口；回到练习页，按 Ctrl + Shift + 1 一次。
3. 看题图飞入→小幽灵等待→答案出现。正确答案是 B，60千米/小时。字母和数值表达可以不同，意思必须相同。

证据：结果+复制到记事本+历史；记下查题时间、前后次数。

### A06 · 截图目标正确，自己的黑面板不挡题

**结果：□ 未测　□ 通过　□ 不通过　□ 缺条件**

怎么做：

1. 到“设置”→“通用”→“截图目标”先选“整个屏幕”，回到练习页截图。结果后点小题图预览。
2. 检查预览是否是鼠标所在的那块屏幕。留意应用黑面板是否出现在题图里，或变成黑块遮住了题干。
3. 再选择浏览器窗口作为目标，截图并预览；把这个窗口缩小、移动后再试。

证据：用手机拍“题图预览”；记录当时选的是屏幕还是窗口。

### A07 · 两张图合成一道题，单张不自动提交

### A09 · 四张上限、删除、撤销和位置变化

### A10 · 截图飞入、Ghost小幽灵、快速展开收起

**结果：□ 未测　□ 通过　□ 不通过　□ 缺条件**

怎么做：

1. 先只收集1张多图，不再添加第二张。观察题图从来源飞到卡片；飞行应短于约1秒，落地轻轻摆动后稳定。
2. 将鼠标移入顶部小面板展开，移开收起；重复5次，再快进快出5次，观察中途反向是否自然。若手动收起后悬停不展开，点击小幽灵展开。
3. 取消多图。再做一次日常单图，观察小幽灵：空闲有细微活动；等待时有思考动作/点阵；成功时有短暂完成反馈。太快看不清就手机录像回放。
4. 再收集一张多图，飞入刚开始就点“取消”；观察是否留下漂浮图片或透明窗口挡住鼠标。

什么算通过：

- 飞入连续、有正确落点；落地后只剩一张对应卡片，没有残影。
- 快速反向不会从头闪一下、卡住或突然跳到错误尺寸。
- 小幽灵在不同状态有对应反馈，完成反馈约1.25秒；具体节奏还要与Mac同场景对照。
- 取消后图片清理，面板外的浏览器按钮仍可点击。

证据：手机录像，尽量60帧；网络等待长短不用于判断动画时长。

2. 在账户页输入开发者提供的无效测试码，点恢复；原账户应保留。再用第二个有效测试码恢复，确认切换到指定测试账户。
3. 退出重启，检查账户仍是刚恢复的账户。跨Windows用户或凭据损坏场景，由开发者在专用系统账户里操作，你观察错误提示。

什么算通过：

- 无效码不覆盖原账户；有效码切换身份，余额不胡乱合并；重启能保留。
- 没有把凭据明文显示到普通设置或错误提示；跨用户/损坏时不自动重建账户掩盖问题。

证据：只记“测试账户A/B”、成功/失败和时间；不得导出恢复码或API Key。

### C06 · 专门制造服务错误，检查恢复和扣次

## 常见卡点

- **启动没反应**：先看顶部和托盘；等30秒仍找不到，记录系统提示和文件位置，交开发者。别复制单个exe、别连续打开很多次。
- **快捷键没用**：先到快捷键页核对显示的组合，再从菜单点击对应功能。菜单能用而快捷键不能用，也要记录快捷键问题；不要把它算通过。引导阶段只接受当前练习要求的模式。
- **次数为0**：找开发者准备测试额度，或按安排主动领取体验；不用自行购买。
- **想在两图测试中重来**：点取消，再从第一张材料重新开始。1张不会自动提交；预览开着会暂停，关闭才重新倒计时。
- **界面变小或消失**：把鼠标移到顶部，或点小幽灵；Ctrl + Shift + 空格可切换显隐；也可从托盘找回。仍找不到按异常记录。
- **窗口关闭后不能截图**：回设置→通用→截图目标，重新选现在打开的窗口。旧窗口与新窗口可能是不同目标。
- **英文报错看不懂**：拍完整提示，不用翻译和猜原因；把项目编号、最后一步操作、时间一起交开发者。
- **系统提示截图权限或安全拦截**：先记录提示，由机器所有者/开发者处理。没有完成授权的项目记缺条件；不要通过关闭系统保护来“解决”。

## 测完交什么

交付时，把“导出结果”得到的TXT和照片/视频一起发给开发者；HTML表格里的自动保存不能替代导出。结果里不要放API Key、账户恢复码、密码。

A全部通过只能说明“本机基础流程通过”。B/C有缺条件，必须列为待验收，不能写“Windows全部验收完成”。凡是启动失败、查题无法用、重复扣次、旧答案覆盖新题、题图被黑块遮住、跨屏飞入位置错误、崩溃，都要单独报出，不被其他通过项抵消。

问题记录示例：B03；Windows11；左屏100%、右屏150%；来源左、接收右；按Ctrl+Shift+2；预期图片落进卡片；实际跨边界后突然变大；3次里出现2次；证据B03-01.mp4；16:20发生。你只需描述看到的事实，不用判断代码哪里坏了。
