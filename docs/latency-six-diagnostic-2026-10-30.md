## 瓶颈与解释边界

上游请求到首答案平均 **6.257 秒**，已经超过整体 6 秒目标。准入完成平均约 0.132 秒，快捷键到提交平均约 0.458 秒。Q9 上游等待 10.630 秒，其中首推理片段到首答案 9.290 秒，是本轮最慢题。收到首答案后服务端立即发 delta，没有发现全文完成后才发答案。

这些上游区间包含服务商处理、网络与模型生成，不能等同纯模型计算，也不能根据总 token 推断准确的推理 token 数。即便假设本轮所有其他开销归零，平均仍有 6.257 秒；因此仅优化客户端与数据库不足以使本轮样本达标，这不是对所有未来请求的理论下限。

flushHeaders 已部署，但六次客户端 bytes(for:) 返回标记仍接近首段 delta。底层 URLSession 的 response_wait 与该标记差异很大：它们测量层次不同，不能拿 responseHeaders 直接当上游响应头时间。现有数据不能判断是平台、中间网络还是客户端 API 的交付行为；本次没有证明该改动带来首答案加速。下一步应先用免费 loopback 测试复现头与正文的交付时序，再决定是否需要修改客户端，而不是继续叠加虚假状态反馈。
