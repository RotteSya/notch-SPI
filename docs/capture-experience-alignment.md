# 截图与刘海体验统一 · 2026-09-13

> 后续更新：三组入口已改为一键完整捕获，不再手动选区。当前实现和验证见 [一键捕获](direct-target-capture.md)。下文保留该阶段历史记录。

本次在现有 AppKit 实现上统一体验，保留已有账户、请求、人物像和多图提交规则。截图证据来自本次本地 QA 应用，题图为合成数据。未请求正式模型、未更改生产服务。

## 审查与修改

1. **入口不一致（高优先级，代码及菜单可访问性树确认）**：旧“保存为材料”“选择题目区域”含义与新方案冲突，后者绕过统一截图入口。现在菜单首先提供截屏查题、多图查题、性格测试，结果区也进入同一流程。Carbon 独占快捷键投递；菜单只展示当前绑定，不注册第二套组合键。
2. **状态含义不清（高优先级，实机截图确认）**：旧等待态（本地验证素材：`output/ux-alignment/02-before-waiting.jpeg`，不随源码发布）标题显示“就绪”。现在明确显示正在选区、等待下一张、即将提问、提交及完成；收集时隐藏上一轮答案及恢复操作，取消后展示下一步提示。
3. **信息层级拥挤（中优先级，实机截图确认）**：旧快捷键页（本地验证素材：`output/ux-alignment/01-before-hotkeys.jpeg`，不随源码发布）将规则塞进操作标题。现在以操作名、说明、键帽分层；三种截图与辅助快捷键分组，完整解释 4 秒规则。共享 `CaptureAction` 文案、`CaptureStyle` 字体与几何、`NotchActionButton` 控件样式。
4. **截图反馈不足（中优先级，实机交互确认）**：卡片保留稳定顺序及编号，增加大图预览与文字“取消本轮”；副标题解释等待、选区暂停与重新计时。预览显示 Esc 关闭提示，计时继续；提交、开始选区或轮次变化时关闭预览，避免遮住后续流程。卡槽与飞行共用圆角，保留轻微弹簧、阴影和减少动态效果路径。
5. **模式切换会清空刚开始的截图（高优先级，实测发现并修复）**：新模式开始截图前立即同步上下文范围，防止周期检查误判。新增测试将上下文检查安排在选区尚未完成时，双向验证查题与性格测试切换。
6. **错误与引导恢复不完整（高优先级）**：错误详情显示在正文，不只依赖可能截断的标题；性格测试无效回复转换为恢复提示，原始协议仍保留在业务缓冲区。引导改为打开网页/PDF 的题目，不再要求截取会被应用自身排除规则隐藏的引导示例。

## 保留的业务规则

⌘⇧1 单图自动提问；⌘⇧2 按顺序收集，1 张无限等待，第 2 张起每次成功录入后 4 秒提交，选区暂停，取消或失败恢复剩余时间，整轮只提交一次；⌘⇧9 使用当前人物像。继续沿用当前服务每轮最多 4 张的限制。原有自定义快捷键仍显示实际绑定。

状态刷新合并到同一主线程周期，卡片不随倒计时重建。动画不拥有计时任务；提交和截图轮次继续使用已有独立文件所有权与回调校验。

## 验证边界

实际 UI 检查使用原生 QA 应用与合成截图；菜单入口、选区键盘操作和取消可直接操作，全局 Carbon 快捷键的物理投递仍需人工验收。自动化覆盖默认映射、迁移与角色对应。

连续截图的顺序、计时暂停恢复、快速重复触发及取消迟到回调通过自动化验证。抓取了选区确认后的连续状态，但工具未捕获完整桌面飞行轨迹，因此不将这些帧视作完整动效录屏。真实屏幕捕获、跨显示器、系统“减少动态效果”的实机观感、正式模型答案质量尚未验证。Codex 参考动画受工具访问限制，未核验。

后续复验可使用 `NSPI_QA_EPHEMERAL=1` 和 DEBUG `--qa-screenshot-demo`；加 `--qa-screenshot-single`、`--qa-screenshot-personality`、`--qa-screenshot-picker`、`--qa-screenshot-failure` 分别覆盖对应状态。接入本地服务必须同时使用 `--qa-screenshot-local-service -official.baseURL http://127.0.0.1:18789`，由 `PORT=18789 ./scripts/dev.sh --server-only` 启动隔离 mock。离线模拟答案明确带 QA 标签。
