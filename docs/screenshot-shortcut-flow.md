# 快捷键与刘海截图流程

> 后续更新：三组入口已改为一键完整捕获，不再手动选区。当前实现和验证见 [一键捕获](direct-target-capture.md)。下文保留该阶段历史记录。

2026-09-13，本地实现，尚未发布。

- `⌘⇧1`：框选截屏，成功后缩略图飞入刘海并自动查题。
- `⌘⇧2`：同一轮多图录入。第一张持续等待；第二张起，每次成功录入重新开始 4 秒倒计时。选区期间暂停；取消或失败恢复原剩余时间。
- `⌘⇧9`：相同截图反馈，沿用已有性格测试人物像、连续题上下文与提问能力。
- 一轮允许 2–4 张，顺序提交；上限来自已有官方服务 `max_images=4`，到上限会明确提示。不会把同一题拆成多个收费请求。
- 一轮取消立即废弃选区、录入令牌、倒计时及缩略图。提交前先清理待提交状态；后续截图进入新的会话。上一题请求中仍可录入下一轮，倒计时到期后等待前一请求结束再发送。

## 实现

沿用 AppKit、Carbon 热键和现有三通道提问管线。`context` 的持久化键及角色保留，含义改为多图录入；首次升级迁移占用默认 1/2/9 的其他旧角色，自定义非冲突键保持不变。重新注册先注销旧绑定。Carbon 主线程事件同步进入截图处理，先暂停本轮倒计时，避免异步排队让倒计时抢先提交。

`ScreenshotRound` 以单调时钟管理倒计时，成功录入时立即提交状态，与动画完成回调无关。每次选区独立令牌和控制器 generation 拒绝迟到回调；账户、目标或通道变化保持原绑定隔离。重复按键在同一选区打开期间合并，不并行打开多个选区窗口。

`ScreenshotFlight` 使用无焦点、鼠标穿透的透明面板与 display-link 时钟；沿弧线缩小到 UUID 对应的固定卡槽。`ScreenshotTray` 缓存缩略图，落位时轻微弹簧回弹；倒计时刷新不会重建卡片。减少动态效果时采用落点淡出叠加，取消空间移动、缩放和回弹。全屏捕获按应用排除本应用全部窗口，覆盖飞行中的面板。

当前截图仍使用项目已有的捕获画面选区窗口，支持鼠标拖动、方向键和 Esc。单图或性格测试请求执行期间保持原有串行请求限制；多图录入不受前一查题请求阻塞。

## 验证

新增纯状态机、快捷键迁移及控制器集成测试；覆盖顺序、4 秒边界、单图长时间等待、选区暂停/取消/失败、整轮取消、迟到回调、重复触发、一次性提交及下一轮文件归属。控制器测试替换截图与提交 I/O，实际执行裁剪、文件录入及提交调度；不调用付费模型。

DEBUG `--qa-screenshot-demo` 配合 `NSPI_QA_EPHEMERAL=1`，在生产截图 I/O 边界提供三张合成题图，驱动真实录入、动画和倒计时。加 `--qa-screenshot-local-service -official.baseURL http://127.0.0.1:18789` 可连接 `PORT=18789 ./scripts/dev.sh --server-only` 的本地 mock 服务，验证真实客户端请求、SSE 与结算流程。该开关只允许 loopback 服务；否则使用显式标识的模拟答案。

已观察到原生单图持续等待、三图倒计时、提交态和自动提交后的 mock 答案，并实际点击整轮取消验证截图清空与操作提示恢复。两次独立 QA 启动各产生 1 次 `POST /v1/captures`，各自测试账户余额 30→29；未使用真实题目或付费模型。验收截图为合成 QA 内容。添加 `--qa-screenshot-waiting` 可停留在单图等待态。

验证结果：Swift 全量 336 项（4 项模型/环境条件跳过），0 失败；最终相关复验 22 项通过。Node 571/571、TypeScript 类型检查、arm64 Release 构建及 `git diff --check` 通过。`scripts/verify.sh` 在 repo-health 被历史归档中的 2270 个失效链接阻断，后续检查已单独执行；没有修改历史归档来掩盖失败。
