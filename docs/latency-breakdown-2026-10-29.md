## 已落地的诊断

### 客户端

- `Sources/NotchSPI/Cloud/OfficialTransportTiming.swift`：仅 Debug 且 `NSPI_LATENCY_TRACE=1`、`NSPI_QA_EPHEMERAL=1` 时创建。记录 runStarted/requestReady/responseHeaders/firstDeliveredDelta/streamFinished，使用单调时钟；只记一次首次事件。
- 复用原 URLSession，通过任务 delegate 读取每个 transaction 的 DNS、连接（包含 TLS）、TLS、请求发送、等待响应、响应接收及连接复用/代理标志。缺失指标不填零；TLS 是连接耗时的子区间，不能重复相加。
- `OfficialAPI.swift` 接入 delegate 与阶段；记录经过长度/字符限制的 `x-vercel-id` 作为生产日志关联键，不记录其他响应头、URL、IP、凭据或正文。任务指标可能在流完成后才回调，不能看到完整答案就立刻杀进程。
- `response_wait_ms` 是 requestEnd→responseStart，混合网络、平台排队、服务端和供应商工作；不能标成模型 TTFT。当前 beginSSE 只调用 writeHead，未显式 flushHeaders，响应头可能随首 delta 一起送出；不能拿客户端收到头的时刻当作服务端完成认证的时刻。responseHeaders 是 URLSession 返回时刻；firstDeliveredDelta 包含流解析/批处理与主线程调度，仍不是原始 socket 首字节。

### 服务端（未部署）

- 新增 `server/src/capture-timing.ts`；通过 `NSPI_SERVER_LATENCY_TRACE=1` 开启，默认关闭，示例登记在 `server/.env.example`。每个请求独立单调时钟/WeakMap，结束时一次性记录，异常或取消保留已到达阶段，不虚构缺失阶段。
- `capture-service.ts` 对 solve 记录认证、输入校验、过期清理、幂等读取、预算预留、额度入账、供应商调用、首 delta 写出、供应商完成及 handler 结束。业务顺序、事务、取消及结算逻辑保持原样。辅助请求仅有部分阶段，不应套用 solve 的完整公式。
- `providers/types.ts` 新增内部 onTiming 回调；`providers/openai.ts` 记录序列化后的上游请求、响应头、首个解析 SSE 事件、首个非空 reasoning、首个非空答案。该回调不序列化进上游 body；隐藏推理内容不转发、不记录。
- 日志只有固定阶段名、时间和验证过的 capture UUID（加现有框架 reqId）；不记录题图、题目、答案、密钥。不开启时不创建计时对象或产生新日志。

### 如何归因

1. 客户端 runStarted→requestReady：本地任务调度、素材读取/base64/JSON 和最后账户校验。
2. URLSession transaction：观察 DNS/连接复用、发送和等待响应，不把缺失项当作 0，也不把各项盲目相加。
3. 服务端 handlerStarted→providerStarted：应用内认证/数据库/校验；不含平台启动、进入 handler 前的上传与 JSON 解析。authReady/reapReady/budgetReady 等进一步定位。
4. upstreamRequest→upstreamHeaders/FirstEvent/FirstReasoning/FirstAnswer：上游网络、供应商排队/预填充/推理及输出的混合跨度。headers 后到 firstAnswer 也不能自动解释为纯模型计算。
5. upstreamFirstAnswer→firstDeltaSent：服务端同步校验与写入响应缓冲，尚不证明字节已到客户端。客户端 firstDeliveredDelta→可用答案 draw 接续原有计时。

不同机器只比较各自单调时钟的持续时间，不直接减客户端/服务端时间戳。即使补齐这些观测，供应商若不提供内部排队/计算 timing，**纯模型计算与供应商内部等待仍无法精确分离**。

## 瓶颈处理决策

当前首要调查对象是传输/平台入口残差与供应商首可见答案，而非继续压缩约 50 ms 的首片段后 UI 链路。代码确有串行认证、reap、幂等读取、预算预留和额度事务，但还没有生产分段证据证明哪步最慢。预算/额度/过期恢复影响正确性和费用，本轮没有盲目并行、缓存或省略。

本轮改动提供可验证的测量能力，**不宣称新增端到端提速**。没有做无依据的网络参数调整、强制预热、模型或输出质量变更。
