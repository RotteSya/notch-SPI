# 管理后台与人工 PLUS

事实所有者：`server/src/admin*.ts`、`plus*.ts`、`billing-{sql,memory}.ts`；客户端使用 `/v1/plus` 和 `/v1/account`。从 [工程入口](../HANDOVER.md) 开始；API 清单见 [official-api](official-api.md)。

## 功能与优先级

P0 为恢复码查询、对象核对、PLUS 预览、确认保存、幂等重试和审计。P1 为运营总览、设备账户搜索/筛选/分页、请求明细、模型分布与人工操作记录。P2 保留原批次/经济报告、质量评测、人工加题、CLI 和最近活动；订单/成本页链接现有可靠报告，并明确覆盖缺口。

不安装依赖；仍为 Fastify + 原生 HTML/CSS/JS、现有 PostgreSQL/SQLite/memory 三种存储。

## 身份与授权

Mac `MainSettingsWindow.copyCodeTapped` 和 Windows 恢复流程使用原设备账户 bearer token 作为恢复码；`devices.token_hash` 是唯一 SHA-256 索引。设备账户 ID 与恢复码不同；恢复同一凭据可能在多个物理设备使用，现有数据不能推导自然人数，也不能精确统计物理设备数。

`POST /admin/ops/lookup` 只在请求正文接收恢复码，先校验管理员，再校验格式、限流、哈希查找。返回账户编号、平台/版本、注册时间、使用量、套餐和到期，恢复码只显示末 4 位。不存在为 404，格式无效为 400，关联不唯一为 409；唯一约束正常情况下排除多对象。

管理接口沿用共享 `ADMIN_TOKEN`、常量时间比对；未配置则 404，密钥错误则 401。密钥不内嵌 HTML，不保存到 localStorage/sessionStorage。新页面有 CSP 哈希、no-store、no-referrer、frame-ancestors none；数据库文本用 textContent。普通搜索在发送前拒绝恢复码；后台接口只接受 POST 正文传递凭据。日志不记录正文、Authorization、管理员密钥或 SQL 异常详情。

操作人姓名/工号为自报；审计额外记录认证密钥的不可逆标识。共享密钥能证明通过认证，不能证明自报姓名真实。独立管理员身份、RBAC、MFA 尚未引入。

## 已确认的人工权益规则

用户在本次实施中确认：每次 1–365 个整数天，一天为 24 小时。当前 PLUS 有效则从其有效到期时间顺延；未开通或到期则从服务端提交确认时刻起算。人工赠送不收费，不改变 Stripe 自然月扣款周期。后续支付权益与人工权益按时间覆盖并集合并，每个北京时间自然日仍只有 400 次，不重复发放。

新开通的预览显示按预览时刻计算的**预计到期**，明确注明以提交确认时刻回算；提交成功回读并显示**实际到期**。有效权益延长显示确定的原到期与新到期。预览有效 10 分钟；如果权益期间或状态发生变更，或跨过到期边界，409 要求重新预览。页面显示完整对象、时长、起算方式、到期和原因后才允许确认。

人工区间从确认时刻起覆盖到延长后的截止时间；已有未到期人工区间保留其原起点。它独立于付款，因此支付取消不会擦除已赠送的区间。已付款但未来开始的周期，只有与当前可用区间相接或重叠时才延长有效截止时间；存在空档则不合并，单独的未来付款不会提前开通。客户端与后台到期筛选使用同一连续覆盖口径。`plus_subscriptions` 与 `plus_paid_invoices` 不被人工操作写入，`topups` 也不记录人工 PLUS 收入。

`ADMIN_PLUS_GRANTS_ENABLED` 默认 `0`，只是上线开关，规则已经确认。关闭开关阻止新发放，仍保持既有人工权益生效。生产启用需另行授权，不能因本地测试已经开启而推断生产已开启。

## 一致性、审计与客户端

预览使用 HMAC 签名，绑定目标、权限凭据、原因、时长、权益摘要和有效期，不含恢复码。确认必须提供 UUID 幂等操作号。同一个操作号+请求重试返回已有记录；换内容复用操作号为 409。更换操作号复用已消费预览也会因权益摘要变化失败。

Postgres 锁定设备行；SQLite 使用已有事务封装；memory 在一个同步执行段提交。人工区间更新和 `admin_operations` 审计在同一事务中。数据库写失败则二者一起回滚。保存成功但响应丢失时，原操作号可在预览过期后继续查询同一成功结果。审计记录操作 ID、账户 ID、操作人、凭据标识、时间、原因、付款/人工权益前后快照。

`/v1/plus.paid_until` 兼容返回当前连续可用权益截止时间，另加 `subscription_paid_until` 与 `manual_until` 以保留来源。`status`、每日额度和 `/v1/account.allowance_sources.plus` 均读取同一权益规则；正式捕获扣题也使用同一规则。客户端刷新时同步。关闭 PLUS 新购买或人工发放开关不会取消已获权益。

Mac/Windows 源码已区分含人工权益的截止时间，提示原订阅扣款周期不变。**已经发布的旧客户端尚未取得此文案修复**：接口与扣题可生效，但旧版可能把有效权益截止时间称为“预计续费日”；客户端文案随后续正常发版交付。

## 数据可用性与统计定义

所有新指标版本为 `operations-v1`，日期筛选使用 Asia/Shanghai，起始日包含、结束日不包含，接口使用 UTC ISO 字符串。范围最多 90 天。SQL 中聚合及分页；明细默认 25 条、最多 100 条，稳定排序。设备列表默认全部注册日期，勾选后才按上方日期筛选注册时间。当前套餐状态不做历史回溯。统计包含内部/测试标记设备；不能当作排除内部流量后的商业口径。

| 指标 | 范围与分母 | 来源与限制 |
| --- | --- | --- |
| 累计设备账户、有效 PLUS、未来 7 天到期 | 查询时全库快照 | devices、plus_subscriptions、admin_plus_entitlements；不是人数 |
| 新注册 | 期间 created_at | devices；与列表“按注册时间筛选”一致 |
| 发起请求账户 | 期间 capture_requests.device_id 去重 | 仅已受理请求，不是 App 打开/登录活跃 |
| 请求数 | 期间创建的请求行 | 包含求解/解释/恢复；不包括额度/鉴权等入场拒绝、请求前的截图失败 |
| 可用答案率 | terminalState=usable / 非 pending 请求 | 无分母显示 —；retake/no_result/canceled/failed 均在已结束分母 |
| 平均完成耗时 | 存在 finishedAt 的请求 | finishedAt-createdAt；含服务端持有/恢复时间，不是纯模型推理或首字延迟 |
| 每日趋势 | 请求创建时间所属北京时间日期 | 显示有记录的日期；点击日期下钻到相同窗口 |
| 失败原因 | 期间 failed 请求，最多 20 类 | terminalReason；空原因分组 unknown |
| 模型尝试 | 父请求创建时间窗口，最多 50 组 | model_attempts，按模型/提供方/币种；重试单独计数 |
| 已知估算成本小计、缺失次数 | 同模型尝试范围 | metadata.costMicros；按币种分开；null 为未知，非供应商账单或财务实付 |
| 操作记录 | admin_operations.created_at | 本版开始的人工 PLUS；分页、日期/账户筛选及完整前后快照 |

设备详情的累计成功扣题是历史总计；余额更新时间不是最后在线时间。现有热键/引导信号保留，只反映客户端上报。产品事件存在但受匿名采集开关与保留期影响，此版不伪装为完整 DAU。

## 数据缺口与后续采集

- 产品总收入：原经济报告有题包收款、退款/争议和费用证据，但明确不含完整 PLUS 收款。`plus_paid_invoices` 目前存已付周期与固定目录金额，缺少可统一对账的付款时间、退款、手续费和净额；不能用行数乘价格作为总收入。后续应接入发票/支付意图/余额交易的不可变事实和退款关联，再汇总。
- 供应商实际账单：现有预算/估算/核对接口继续保留；此页只展示模型尝试中的估算。需完整导入供应商账单与请求关联，才能显示实际成本与总利润。
- 自然人数、物理设备数量：缺少独立用户/设备安装身份模型；不能从一个恢复凭据反推。
- 完整 App 活跃与入场失败率：需明确事件采集口径和覆盖范围后新增服务端事件/聚合，不默认开启匿名遥测或收集敏感内容。
- 历史管理操作：加题仍有原 topups 审计；历史 CLI 切换等缺少完整操作人/前后快照，未回填或伪造。新独立账号体系及所有管理写接口统一审计仍是后续范围。
- Postgres 测试必须指定库名含 test 的独立数据库，并使用测试 schema，绝不能借用生产库。2026-11-11 已使用现有 PostgreSQL 17.11 启动回环临时实例，完成实库验收；测试数据库与运行目录随后清理。未配置 `TEST_POSTGRES_URL` 的其他运行仍不代表实库验收。

### 内部／测试费用分类

运营总览、请求与模型、订单与成本按当前 `devices.is_internal=1` 或 `platform=release-qa` 分为内部／测试，其余归真实用户。分类更新会重算历史视图，不改费用账本。费用汇总不受模型前 50 行限制，按币种独立展示；按父请求创建时间筛选，含失败和重试，因此跨日调用与预算窗口可能不同。已知费用优先采用预算账 observed/reconciled/released 的 actual，否则使用模型 metadata.costMicros；未知费用保持未知，provisional 暂估、预算 booked 和未入预算次数分别显示。此分类仅用于统计，不授予内部账号特权，也不代表供应商最终账单。
